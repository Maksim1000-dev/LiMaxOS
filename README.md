# LiMaxOS

Мини-ОС для x86 в реальном режиме: двухступенчатый загрузчик на NASM и
графический рабочий стол с окнами, мышью, панелью задач, часами и терминалом.
Ядро работает через линейный framebuffer 8 бит на пиксель двумя способами:
через VBE (`INT 10h`, функции `4F00/4F01/4F02`) на реальных видеокартах и
через Bochs/QEMU dispi (порты `0x01CE/0x01CF`) там, где VBE недоступен.
Разрешение меняется на лету без перезагрузки, а список доступных режимов
строится динамически по данным адаптера и объёму видеопамяти.

## Запуск

Дважды кликни `START.BAT`.

Скрипт сам:

1. собирает `boot/boot.asm`, `boot/loader.asm` и `kernel/kernel.asm` через NASM;
2. компилирует `tools/mkimg.c` через GCC;
3. собирает флоппи-образ `build/LiMaxOS.img` (1.44 МБ);
4. запускает помощник `tools/winsize.ps1`;
5. запускает QEMU в оконном режиме GTK с COM1 на TCP-порту 4444.

Собрать без запуска:

```bat
START.BAT build
```

Запуск без паузы после закрытия QEMU:

```bat
START.BAT nopause
```

## Разрешение и масштаб

Логический рабочий стол всегда равен половине физического разрешения
(`UI = SCREEN / 2`), а все примитивы, шрифт и мышь масштабируются ровно ×2.
Поэтому интерфейс одинаково выглядит на любом режиме:

| Физическое разрешение | Логический стол | Масштаб UI |
| --- | --- | --- |
| 640×360 | 320×180 | ×2 |
| 1280×720 | 640×360 | ×2 |
| 1920×1080 | 960×540 | ×2 |
| 2560×1440 | 1280×720 | ×2 |
| 3840×2160 | 1920×1080 | ×2 |

Конкретный набор режимов зависит от видеокарты и её памяти. Ядро принимает
только 8-битные packed-pixel режимы с линейным framebuffer, отбрасывает те,
что не помещаются в видеопамять или в RAM над back buffer, и сортирует
оставшиеся по площади. В QEMU `-vga std` это Bochs dispi, в
`-vga cirrus` и `-vga vmware` — VBE.

В правом нижнем углу панели задач в две строки показаны время в 24-часовом
формате и дата `DD.MM.YYYY`. Над панелью задач на рабочем столе отображается
водяной знак с текущим физическим разрешением.

## Курсор и нагрузка

Курсор хранится в back buffer. При движении восстанавливается только старая
область 20×28 пикселей, затем рисуется стрелка в новой позиции. Копирование
выполняется dword-циклом с байтовым хвостом, без `rep movsb` по LFB. В простое
и при движении мыши QEMU занимает около 3–5% CPU, а полная перерисовка сцены
происходит только при реальном изменении интерфейса: hover, окна, меню.

## Автоподстройка окна QEMU

QEMU запускается в обычном оконном режиме: сверху видны заголовок и меню QEMU.
Картинка не растягивается — гость меняет реальное разрешение под клиентскую
область окна.

Помощник `tools/winsize.ps1`:

- измеряет клиентскую область окна QEMU (DPI-aware);
- вычитает высоту меню GTK (на текущей машине 29 px);
- округляет ширину до кратного 8, а высоту до чётного числа;
- ждёт 350 мс после отпускания края окна и отправляет размер в гостя по COM1;
- после смены режима подгоняет окно так, чтобы гость был ровно 1:1, без
  растяжения на несколько пикселей;
- игнорирует свёрнутое окно и не устраивает цикл «размер → режим → размер».

При старте ядро просит 1280×720. Если такого режима у адаптера нет, выбирается
ближайший по площади: например, 1024×768 на Cirrus или 1152×864 на VMware.
Если помощник окна не подключился, остаётся режим, выбранный при старте.

### Протокол COM1

| Направление | Сообщение | Значение |
| --- | --- | --- |
| host → guest | `1280x720\n` или `MODE 1280x720\n` | клиентская область окна без меню |
| guest → host | `HELLO\n` | гость готов, можно прислать размер |
| guest → host | `MODE 1280x720\n` | текущий реальный режим |
| guest → host | `LOCK\n` | выбран ручной пресет, авто выключено |
| guest → host | `AUTO\n` | ручной пресет снят, авто включено |

Сообщения `MODE` от хоста применяются только в режиме AUTO: при ручной
блокировке (`LOCK`) и во время предпросмотра в настройках они игнорируются,
чтобы смена размера окна не сбивала выбранный пользователем режим.

## Рабочий стол

- Иконка **TERMINAL** в левом верхнем углу. Двойной клик открывает терминал;
  один клик выделяет иконку, `Enter` открывает её с клавиатуры.
- Окна перетаскиваются за заголовок и не могут уехать за пределы экрана: при
  уменьшении разрешения они прижимаются к краю.
- Кнопки окна: жёлтая — свернуть, зелёная — развернуть/восстановить, красная —
  закрыть. Свёрнутое окно остаётся кнопкой на панели задач.
- Кнопка **L** в левом нижнем углу открывает меню вверх от панели задач:
  **TERMINAL**, **SETTINGS**, **Restart**, **Shutdown**. `Esc` или повторный
  клик по `L` закрывают меню.
- Окно **TERMINAL** можно тянуть за правый нижний угол. Содержимое буфера
  (80×25) сохраняется при изменении размера и при смене разрешения.
- **SETTINGS** открывается из меню `L` и устроено как остальные окна: его можно
  таскать, сворачивать, разворачивать и закрывать. Слева — панель с кнопкой
  **DISPLAY**, справа — настройки дисплея.

## Настройки дисплея

Окно **SETTINGS** состоит из боковой панели **DISPLAY** (там же показаны
видеобэкенд — `VBE` или `BOCHS` — и число найденных режимов), заголовка с
текущим разрешением, списка режимов и нижней строки состояния.

Список строится динамически, без жёстко зашитых пресетов:

- **AUTO (QEMU window)** — следовать за размером клиентской области QEMU;
  выбирается ближайший поддерживаемый режим по площади;
- **MAXIMUM WxH** — самый большой валидный режим, который помещается в
  видеопамять (back buffer при этом остаётся в RAM);
- далее — все реальные режимы адаптера, отсортированные по площади.

Если строк больше, чем помещается в окно, справа появляется скроллбар:
стрелки, клик выше/ниже бегунка — страница, перетаскивание бегунка — прокрутка.
Окно Settings по умолчанию 380×280; на маленьком экране (например, 640×360)
оно сжимается до 320×160, показывает около пяти строк и всё равно остаётся
работоспособным.

Выбор строки сразу применяет режим как предпросмотр. Внизу загорается
`PREVIEW Ns` и идёт обратный отсчёт 10 секунд:

- **APPLY** (или `Enter`) подтверждает выбор; ручной режим запоминается,
  отправляется `LOCK`, статус становится `MANUAL - auto is paused`;
- **CANCEL**, `Esc`, закрытие или сворачивание окна, а также истечение
  10 секунд возвращают режим, который был до начала предпросмотра;
- выбор другой строки во время предпросмотра сохраняет исходный режим и
  перезапускает таймер;
- **AUTO** подтверждается так же, отправляет `AUTO` и возвращает следование
  за окном (`AUTO - linked to window`).

`Up`/`Down` перемещают выбор по списку, `Enter` подтверждает, `Esc`
отменяет. Пока идёт предпросмотр, сообщения `MODE` от помощника окна
игнорируются и не сбивают выбранный режим.

## Терминал

Команды вводятся в окне TERMINAL. `Enter` выполняет команду,
`Backspace` удаляет символ.

| Команда | Что делает |
| --- | --- |
| `HELP` | список команд |
| `VER` | версия LiMaxOS |
| `DIR` | фиктивный список файлов |
| `CLS` | очистить экран |
| `ECHO текст` | напечатать текст |
| `MEM` | обычная/расширенная память |
| `TIME` | время из RTC |
| `DATE` | дата из RTC |
| `SETTINGS` | открыть настройки дисплея |
| `ABOUT` | информация о системе |
| `REBOOT` | перезагрузка |
| `POWEROFF` | выключение QEMU через ACPI |
| `HALT` | остановка процессора |
| `GSOD [code]` | показать зелёный экран смерти; без кода используется 516 |

## Зелёный экран смерти (GSOD)

При критической ошибке LiMaxOS показывает зелёный экран смерти:

```text
:(
SOMETING WENT WRONG
SYSTEM HALTED
CODE OF ERROR: 516 CHECK SUM FALIED
```

В графическом режиме экран рисуется через VBE/LFB: крупный смайлик `:(`
и три центрированные строки. Если видеорежим ещё не настроен (ошибки
boot-сектора и загрузчика), используется текстовый зелёный экран 80×25.
После показа экрана система выполняет `CLI` и уходит в `HLT` — помогает
только перезагрузка.

Каталог из 80 кодов и названий находится в `include/errors.inc`:

| Диапазон | Назначение |
| --- | --- |
| 100–109 | загрузка, диск и образы |
| 200–209 | память и процессорные исключения |
| 300–309 | видео, VBE и framebuffer |
| 400–409 | клавиатура, мышь, COM1, RTC |
| 500–519 | ядро и среда выполнения |
| 600–609 | оконный менеджер, терминал и UI |
| 700–709 | оборудование и таймеры |

Процессорные исключения 0–7 перехватываются сразу, а 8–15 — после переноса
PIC на векторы 0x20–0x2F. Векторы BIOS 0x10–0x1A не затрагиваются. Команда
`GSOD [code]` в терминале позволяет проверить любой код каталога, например
`GSOD 516`.

## Что происходит при загрузке

1. **Boot-сектор (512 байт)** читает первый сектор `LMAXLDR.SYS`, проверяет
   заголовок `LiMaxLdr`, узнаёт количество секторов и догружает остальные.
2. **LMAXLDR.SYS** рисует чёрный неоновый экран, определяет RAM через BIOS,
   читает `CORE.SYS` по одному сектору с LBA 64 и обновляет полосу только
   после успешного чтения.
3. После чтения проверяется контрольная сумма ядра, выполняется реальный тест
   320 КБ памяти (запись/проверка `AA55` и `5555`) и происходит переход в ядро.
4. **CORE.SYS** определяет видеобэкенд: Bochs/QEMU dispi (`1234:1111` или
   порты `0x01CE/0x01CF`) либо VBE (`INT 10h AX=4F00/4F01`), строит список
   допустимых 8-битных LFB-режимов с учётом видеопамяти, переводит PIC на
   векторы 0x20–0x2F, включает таймер, клавиатуру и PS/2-мышь, после чего
   запускает рабочий стол.

Задержка 25 мс между секторами добавлена только чтобы прогресс был виден
глазами. Она не двигает полосу сама по себе — полоса меняется после реального
чтения. Уменьшить/убрать задержку можно в `boot/loader.asm` по меткам
`mov ax, 25` / `call delay_ms`.

## Структура проекта

```text
START.BAT              сборка, запуск QEMU и помощника
boot/boot.asm          boot-сектор, LBA 0
boot/loader.asm        LMAXLDR.SYS, LBA 1
boot/gsod.inc          текстовый GSOD загрузчика (80×25)
kernel/kernel.asm      CORE.SYS: точка входа и главный цикл
kernel/gsod.inc        графический/текстовый GSOD и обработчики исключений
include/errors.inc     каталог из 80 кодов ошибок и общие строки GSOD
kernel/gfx.inc         VBE/Bochs probe, режимы, палитра, шрифт, примитивы, курсор
kernel/mouse.inc       PS/2-мышь, IRQ12
kernel/irq.inc         PIC, таймер, клавиатура, IRQ0/IRQ1
kernel/rtc.inc         часы/дата через CMOS
kernel/serial.inc      COM1 и протокол размера окна
kernel/term.inc        буфер терминала и команды
kernel/ui.inc          рабочий стол, окна, панель задач, часы, меню L
kernel/settings.inc    динамический список режимов, предпросмотр, APPLY/CANCEL
tools/mkimg.c          сборщик образа и патчер заголовков
tools/winsize.ps1      автоподстройка разрешения под окно QEMU
tools/qmon.ps1         команда в монитор QEMU (TCP 4445)
tools/sendkeys.ps1     ввод клавиш в гостя через монитор
tools/qwin.ps1         свернуть/развернуть/измерить окно QEMU
tools/printwin.ps1     снимок окна QEMU через PrintWindow
tools/ppm2png.py       конвертер скриншотов QEMU (только stdlib)
tests/                 логи тестов и скриншоты
build/                 результаты сборки
```

## Формат образа

- 1.44 МБ, геометрия 80 цилиндров / 2 головки / 18 секторов.
- LBA 0: boot-сектор с сигнатурой `55 AA`.
- LBA 1: `LMAXLDR.SYS`, заголовок 32 байта:
  `LiMaxLdr`, число секторов, сегмент загрузки, точка входа, размер,
  контрольная сумма.
- LBA 64: `CORE.SYS`, такой же заголовок с магией `LiMaxOSK`.

`mkimg.exe` сам считает количество секторов и контрольные суммы, поэтому
исходники можно менять без ручной правки размеров.

## QEMU

Запускается так:

```bat
set GDK_SCALE=1
set GDK_DPI_SCALE=1
qemu\qemu-system-i386.exe -name "LiMaxOS" -machine pc -m 16M ^
  -drive "file=build\LiMaxOS.img,format=raw,if=floppy" ^
  -boot a -rtc base=localtime -vga std ^
  -serial tcp:127.0.0.1:4444,server,nowait ^
  -display gtk,zoom-to-fit=on,show-menubar=on,keep-aspect-ratio=off,gl=off
```

Окно остаётся оконным: сверху видны заголовок и меню QEMU, его можно таскать,
сворачивать, разворачивать и растягивать за края. При растягивании гость
получает новое реальное разрешение, а не растянутую картинку.

`-vga std` включает Bochs dispi: режимы синтезируются из объёма видеопамяти.
С `-vga cirrus` и `-vga vmware` ядро идёт через VBE и использует реальный
список режимов адаптера (на Cirrus это, например, 640×480…1280×1024, на
VMware — до 1600×1200).

`Ctrl+Alt+F` — полноэкранный режим без меню (не обязателен для работы
автоподстройки), повторное нажатие возвращает окно.

`-m 16M` даёт около 639 КБ обычной памяти и ~15 МБ расширенной; back buffer
занимает область от `0x00400000`, а режимы фильтруются по доступной
видеопамяти, поэтому на слабом адаптере список будет короче.

В простое главный цикл уходит в `HLT` и просыпается по прерываниям таймера,
клавиатуры или мыши, поэтому QEMU не нагружает процессор на 100%.

## Тесты и логи

Все логи и скриншоты складываются в `tests/`:

- `tests/winsize.log` — измерения окна, отправленные размеры и ответы гостя;
- `tests/*.png` — ключевые скриншоты гостя через монитор QEMU (PPM — рабочий
  формат `screendump`, в репозитории оставлены только PNG);
- `tests/click.ps1` — клик по логическим координатам через монитор QEMU.

Для теста без видимого окна удобно запускать QEMU с монитором:

```bat
qemu\qemu-system-i386.exe -display none ^
  -drive "file=build\LiMaxOS.img,format=raw,if=floppy" -boot a ^
  -monitor tcp:127.0.0.1:4445,server,nowait
```

Закрывать QEMU нужно командой `quit` в мониторе, а не завершением процесса.
